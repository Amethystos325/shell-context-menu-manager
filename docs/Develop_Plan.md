# Shell UI 管理器开发计划（当前版）

## 1. 项目目标

1. 提供 Nilesoft Shell 配置的可视化编辑能力，降低手工维护 `shell.nss` 的复杂度。
2. 保证发布安全：保存前校验、写入前备份、失败可回滚。
3. 保证预览真实性：系统菜单数据来自注册表与 COM 探测，不走 mock 回退。
4. 将“预测渲染 vs 实机菜单”的差异收敛流程脚本化，并作为固定回归门禁。

## 2. 当前范围（已落地）

1. 配置核心链路
- 支持 `parse / serialize / validate / diff`。
- 支持真实样例 `res/*.nss` 回归校验。
2. 编辑器能力
- 三栏编辑：树结构、属性面板、源码同步。
- 支持 `menu / item / separator` 节点操作与规则中心编辑。
3. 发布闭环
- 保存前 Diff 预览。
- 自动备份、备份列表、回滚恢复。
- 应用配置动作与日志追踪。
4. 预览与一致性
- 支持系统菜单快照 + Shell 规则合并渲染。
- 支持多场景基线和结构/视觉/实机回归脚本。

## 3. 当前阶段重点（阶段 6）

1. 视觉回归扩展
- 从单图对比扩展到多场景批处理。
- 输出聚合结果，明确每个场景的差异分布。
2. 阈值与策略固化
- 固化 `missing / extra / order / submenu / disabled` 的阈值策略。
- 对 OCR 不稳定项增加容错规则，避免误报阻断。
3. 数据覆盖补齐
- 继续扩展 `CommandStore` 与 COM 采样覆盖。
- 优先收敛子菜单层级与禁用态差异。
4. 发布门禁接入
- 将 `stage6:real-regress` 作为发布前固定检查项。
- 保留失败明细输出，便于快速定位回归来源。

## 4. 验收口径（阶段 6）

1. 结构差异在阈值内：`missing / extra / order / submenu / disabled`。
2. 视觉差异在阈值内，且多场景运行结果稳定。
3. 回归门禁通过：`stage6:regress` + `lint` + `typecheck`。
4. 差异策略与基线变更有文档记录并可追溯。

## 5. 非目标（当前不做）

1. 不新增与一致性收敛无关的大功能。
2. 不扩大平台范围（仍以 Windows 为交付主线）。
3. 不在当前阶段引入高风险重构（优先增量修正和可回归验证）。

## 6. 回归产物管理

1. `artifacts/` 目录用于临时回归产物（截图、日志、调试文件）。
2. 每轮回归验证结束后清理 `artifacts/` 临时文件，仅保留目录结构。
3. 需要长期保留的基线文件继续放在 `docs/Stage6_*_Baseline.json`。

## 7. 文档分工

1. 本文件：记录当前目标、范围边界、阶段重点与验收口径。
2. `docs/Develop_Progress.md`：记录当前阶段状态、里程碑和下一步执行项。
3. `docs/Stage6_Diff_Checklist.md` 与 `docs/Stage6_*_Baseline.json`：记录差异收敛明细与基线。
